### 1.1 现成件（这次没重写）

- 取流：`PlayerApi.getBangumi()`，`pgc/player/web/v2/playurl` + 失败回退 v1，参数带 `ep_id`/`season_type`/`season_id`（`PlayerApi.java:421`）。
- 返回 `durl` 分段 mp4，音视频已混合，**不需要 remux**（`PlayerApi.java:486`）。
- 落盘/续传/候选 CDN 重试/弹幕/字幕/本地列表扫描：全部走 DownloadService 既有代码。
- 播放地址**不落库**，worker 每次下载前现取，避免几小时后 403。

### 1.2 明确没做的事

- **批量选集缓存**：本轮只缓存当前选中的一集（按钮在番剧信息页，与「播放」并列）。
- **DASH/4K**：`getBangumi()` 用 `fnval=1`（durl），上限 1080P；要 4K 需给 PGC 单独开 `fnval=4048` 分支。
- **番剧字幕适配**：仍调 UGC 的 `getSubtitleLinks(aid, cid)`，返回空时静默跳过（`downSubtitles` 有 try 且调用处不检查返回值，不会拖垮任务）。
- **批量删除/私信按钮/UI 收敛**：均为同日前几批，不在本轮范围。

## 3. 已知限制与未验证项

1. **完全没有实机点过**（用户说明由他手动测试）。编译 + SQLite 内存库迁移验证 **不等于** 真机 DB 升级成功，也不等于真的下下来了一集。
2. **多分段 durl 可能只下第一段**：`PlayerApi.getBangumi()` 与在线播放同口径，只暴露 `durl.get(0)` 的 CDN 候选列表（`PlayerApi.java:486`）；`downFile(List)` 是 CDN 候选重试，不是多段拼接。B 站 PGC 多数返回单段，但**我没有实测过长剧/电影是否多段**。若发现下下来的视频时长不对，这是第一嫌疑。
3. **会员专享 / 付费集**：无权限账号取流会抛 `JSONException("获取番剧播放地址失败")`，走 worker 既有的「下载链接获取失败」提示，**没有针对 -10403 之类的专用文案**。
4. **清晰度是硬编码 4 档 qn**：服务端会给不高于请求的最高可用档；没有预先探测 `accept_quality`，所以列表里可能显示实际拿不到的档位。
5. **播放地址时效**：durl 通常 2 小时过期，任务排队过久会失败（与 UGC 下载的既有口径一致，worker 每次现取已缓解）。
6. **无谓的网络请求**：`getBangumi()` 会顺带查一次本集续播进度（`HistoryApi.findEpisodeProgressMs`，仅 v2 没带进度且已登录时才发），下载场景用不到但不会致命（内部有 try）。
7. **封面为空会让任务失败**：`GlideUtil.url("")` 返回空串，worker 下载封面失败即整单 failed。Fragment 已兜底到 `bangumi.info.cover`；这是沿用 UGC 的既有口径，本轮没改。
8. **风控/合规**：批量连续下多集可能触发限流；B 站对 PGC 内容下载传播的限制比 UGC 严，功能上线与否由用户决定（已在上轮评估里提示）。
9. **DB 迁移只在内存 SQLite 验证**：真机上 `download.db` 可能是 v2/v3 逐级升上来，`oldVersion < 4` 分支仍保留原有的「ALTER 失败就 drop table」语义——那一支本轮**没有改**，历史数据风险仍在（仅当 v4 迁移当年失败过才会触发）。

## 4. 下一步需要你做什么

1. 装 `~/Desktop/ReBiliTerminal-1.3.7-UI.apk`（已用无线 adb 覆盖安装，可直接使用）。
2. 复测顺序：
   - 先打开「下载列表」→ 确认**原有下载记录还在**（验证 DB v5 迁移没丢数据）；
   - 随便进一部**免费番剧**详情页 → 选一集 → 点「缓存」→ 选 720P → 去下载列表看进度；
   - 下完后进「本地视频」→ 确认能播、时长完整、弹幕能加载；
   - 再试一部**会员番剧**，看失败提示是否看得懂；
   - 最后确认番剧详情页三个按钮（播放/追番/缓存）在手表/窄屏上没有挤成一团。
3. 若第 2 步能跑通，再决定要不要做「批量选集缓存」和「DASH 4K」。
4. 出现任何失败，把 `logcat` 里 `download` / `番剧取流` 相关行给我，我按实际报错修。

⚠️ **DB 版本不能靠回滚代码降回去**：真机上装过这一版后 `download.db` 已是 v5（多三列）。
代码回退到 v4 时 `SQLiteOpenHelper` 会因「数据库版本高于代码版本」抛异常。
若确需回退，请先卸载应用或手动 `adb shell` 删掉 `download.db`（会丢全部下载记录与已下文件）。
