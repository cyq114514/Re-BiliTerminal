## 3. 已知限制与未验证项

1. **没有手表/手机实机验证**。本批全部结论来自静态代码 + 编译 + APK 资源 dump，**没有任何一项在设备上点过**。复测方法见 §4。
2. **主题色改动只在「进入页面时」生效**：`getPrimary()` 是在 bind / setStrokeColor 那一刻读的，`ThemeColorActivity.setSeed()` 不重启进程（这是既有设计）。所以在配色页改完色返回，已经画好的旧页面要重新进入才更新——`EpisodeCardAdapter`、`HotSearchAdapter` 等既有迁移点同样如此，本批没有引入新问题，也没有解决它（要解决得给每个适配器注册 `OnThemeChangedListener`，属另一批）。
3. **`sel_filter_chip` 仍是一颗雷（C6 的实体）**：它的 selected 分支写死 `@color/bili_pink`，`ThemeApplier` 不管 `StateListDrawable`。当前 4 个第三方源布局都没调 `setSelected`，所以看不到问题；**但谁以后在那里加选中态，自定义主题下就会露出默认粉**。要么按 DESIGN.md 在 Java 重建背景，要么把 selected 分支也换成代码着色。
4. **触控目标只改了音量键**：全项目按钮高度实际有 30dp（顶栏/DESIGN.md 口径）、36dp（页内按钮）、40dp（手表口径）三档并存。W4/W5 单独抬到 40dp 会在这三档之外再造不一致，**需要先定一档**再统一改（见 §5）。
5. **`activity_player.xml` 的「加载中」仍是 10sp**：它和同组「OwO」在同一个 loading 覆盖层里，只改一个会留下混排字号，且该文件正被另一批改动动过，故整组留待一起处理。
6. **`PrivateMsgAdapter` 气泡两处未动**：`:113` 自己的气泡底仍是 `R.color.pink`（旧粉 `#FBFB8787`）、`:117` 对方气泡是 `#78242424`。前者**不属强调色语义**（"我方消息=粉色"是聊天配色），改成主题色会改变观感，需要拍板。
7. **互关徽章跟随主题只覆盖两处列表**：`FollowGroupAdapter`、`UserListAdapter`。`PrivateMsgSessionsAdapter` 也用 `cell_user_list`，但徽章默认 GONE，未处理。

## 4. 下一步需要用户做什么

1. 装机复测（debug 包即可）：
   - 设置 → 界面 → 主题配色，选一个非默认色（如绿色）→ 依次进「播放器设置」「收藏夹选择夹」「番剧选集」「关注分组」「分P选择」看选中描边/文字是否随色。
   - 听歌页（`activity_audio_player`）看音量键点按是否还容易点空、40dp 后一排是否仍居中不挤。
   - BGM 条目页、听全部卡片看 11sp 说明文字是否仍单行不折。
2. 需要拍板的三件事（我不擅自改）：
   - 弹窗（清晰度/字幕/分P）的「反色选中」是否统一为主题色胶囊；
   - 页内按钮/触控目标统一到 30 / 36 / 40 哪一档；
   - 私信气泡是否跟随主题色。
3. 若确认无需继续，本批可与「缓存听歌与网络错误」「性能审计修复」一起进 1.3.5 的发版说明（`更新日志.md` 章节已同步，尚未改 `UpdateLog.java` / readme / 官网）。
