# Re:BiliTerminal UI 视觉系统审查报告 + 升级方案（2026-11-14）

> **状态：只读审查产出。本文不含任何代码改动，方案未获确认前不动代码。**
> 基线：`HEAD ef0fe1d`（1.3.7 / versionCode 20261118），工作区干净。
> 编译配置：minSdk 19 / targetSdk 26 / compileSdk 33 / Material 1.9.0。
> 规模：Java 467 个文件、布局 154 个、drawable 108 个（全 XML，无位图）、values 7 个文件。
> **本轮没有编译、没有装机、没有跑测试**。所有结论来自静态读取 + 统计命令，凡涉及"观感"的都必须装机复核（见 §7）。

## 1. 现有设计语言（升级必须保留的东西）

项目不是通用 Material 应用，而是一套自定义的「暗底 + 半透明发丝描边卡 + 单一强调色」语言，移植自 Re-WearBili。

| # | 设计元素 | 现状实现（证据） |
|---|---|---|
| 1 | 底色 | 纯黑 `@color/bgblack`（`themes.xml:5`），无灰阶分层 |
| 2 | 氛围光 | `AmbientBackground` 顶部一枚径向强调色光晕，alpha 0x59→0，1/4 分辨率缓存（`AmbientBackground.java:44,149-159`） |
| 3 | 卡片 | 30% 灰底 `#4D262626` + 0.5dp `#363636` 描边 + 10dp 圆角 + **零投影 + 零 ripple**（`styles.xml:6-18`、`colors.xml:23-26`） |
| 4 | 按压反馈 | 卡片/按钮缩放 0.9、150ms（`animator/press_scale.xml`）；列表行用 `selectableItemBackground` ripple（60 处） |
| 5 | 顶栏 | **无底色、无分割线**：`pageName`（14sp bold，起始箭头）+ 右侧 `TextClock`，垂直 3dp / 起始 8dp（`activity_base.xml:7-37`） |
| 6 | 强调色 | 唯一来源 `ThemeManager`，默认 B 站粉 `#FE679A`；只接管强调，其它颜色不经过它（`ThemeManager.java:15-36`） |
| 7 | 主菜单 | 48dp 圆形描边按钮 + 11sp 标签 + 10sp 角标（`cell_menu_grid.xml`） |
| 8 | 大标题卡 | 渐变描边卡 `background_card_gradient_border`（0.4dp `#363636`→透明），作 `biliCardBackground` 主题属性（`themes.xml:20`） |
| 9 | 双世界 | `NEW_UI_DESIGN` 开关：关掉走 `ThemeOverlay.BiliClient.Classic`（6dp 圆角 + `#cc262626` 实底 + ripple，`styles.xml:37-56`） |

**手表适配机制（现状，不得替换）：**
- **没有任何 `values-sw*` / `layout-*dp` 资源限定符**，全项目只有一套 `res`（实测 `find` 仅 5 个目录）。
- 运行时四条通道：① `player_ui_round` 开关 → `BaseActivity` 给 `android.R.id.content` 加水平 8%/底部 6% 安全边距（`BaseActivity.java:129-135`）；② `setRound()` 重排顶栏（时钟居中、标题 18% 内边距、按钮贴左，`BaseActivity.java:475-528`）；③ 自绘 `Rotary*` 滚动组件（26 个 RecyclerView + 36 个 ScrollView + 4 个 NestedScrollView）；④ 用户可调 `density` 覆盖（`BaseActivity.java:143`）。
- 圆屏安全边距在弹窗里是独立一套：宽度 84%、四边 4%/3%（`AdaptiveDialog.java:313-321`）。

**结论：这套语言风格清晰、辨识度高，不需要重做。问题全部在"同一语言的多套实现"和"细节档位失控"上。**

## 4. 升级方案（分批、串行、每批可编译可回滚）

**总原则：只做"收敛已有语言"的事，不新增视觉装饰；不引入渐变/发光/毛玻璃/新图标体系；不动播放器自成体系；不动业务与生命周期。**

### 批次 1｜token 补位（零视觉变化，纯新增）

- 新增 `dimen`：`radius_card=10dp`、`radius_chip=14dp`、`radius_badge=3dp`、`page_padding=6dp`、`card_gap=2dp`（数值全部沿用现值，**不引入新数值**）。
- 新增语义色：`text_secondary`（次级）/`text_tertiary`（弱提示），取值待 §5 拍板。
- 修复 `styles.xml:81` 的伪注释（R2）。
- 影响文件：`dimens.xml`、`colors.xml`、`styles.xml`。风险：零（除 R2）。

### 批次 2｜圆角收敛（C4 + 圆角 9 档）

- 9 处非 token `cardCornerRadius` 按语义归类：**列表项卡片**（`cell_coin_log`/`cell_exp_log`/`cell_follow_group`/`cell_login_record`/`cell_bgm_grid`/`item_account`/`activity_app_auth`）→ 10dp；**圆形头像**（`cell_up_avatar` 28dp）与 **播放器封面**（`activity_audio_player` 16dp）保留（它们是"形状"不是"卡片"）。
- `background_interaction_choice.xml` 12dp → 10dp；`bg_share_input` 18dp / `bg_share_handle` 2dp / `bg_audio_capsule` 15dp 保留（分享面板与胶囊是独立形状，改会变形）。
- 影响 8 个文件。风险：低。回滚：单文件 `git checkout`。

### 批次 3｜输入框统一（C2）

- `background_edittext` 的**描边与圆角**对齐新版（2dp `#cc262626` → 0.5dp `#363636`，6dp → 10dp）；**底色保持不变**（`#80242424` 比搜索框浅，是输入框语义，不合并）。
- `background_edittext_privatemsg`（私信）只同步圆角/描边宽度。
- 影响 13 个页面（11 + 私信 + 定义文件）。风险：中低（登录页观感变化最明显，需截图对比）。回滚：单文件。

### 批次 4｜chip 收敛 + 修雷（C3 + R1）

- `sel_filter_chip` 的选中分支从 XML 写死改为**代码着色**（按 DESIGN.md「跟自定义主题的强调色不要写死在 XML selector 里」）：在 `ThemeApplier` 增加 `StateListDrawable` 分支或在调用方重建背景。
- 选中态视觉：保留"实心强调色"，只把圆角 14dp 统一到 `radius_chip`、并去掉未选中态的黑 8%（改为卡片灰底 + 描边，与 `sel_refresh_chip` 同语言）。
- 影响：`ThemeApplier.java`、`sel_filter_chip.xml`、7 个页面。风险：中（7 页筛选条观感统一，需真机确认选中项易辨识）。**此项需拍板（见 §5-Q4）**。

### 批次 5｜次要信息语义化（C5）⚠ 改动面最大

- 把 166 处 `android:alpha` 收敛到 **2 档**：`0.7`（次级）与 `0.5`（弱提示）；把 `0.9/0.8/0.75/0.55/0.6/0.85/0.78/0.86/0.88/0.95` 归并到最近档。
- **不改** `@color/text_gray`（54 处），**不把 alpha 换成 textColor**：alpha 作用于整个控件（含 compound drawable 图标），换语义会连带改图标颜色，不是等价替换。
- 影响约 40 个布局文件。风险：中（值差 0.05 肉眼几乎不可见，但 0.9→0.7 会让"描述文字"明显变淡，需逐档确认）。**需拍板（§5-Q5）**。

### 批次 6｜设置项统一（C6 + C7）

- `activity_setting_main.xml` 的 38 个内联卡片改为复用 `cell_setting_open` / `cell_setting_switch` 模板（`paddingVertical 7dp` + 名称 14sp + 描述 11sp），消除"主页与子页两种条目"。
- 分组标题统一到 `cell_setting_title`（14sp bold），弃用 `12sp + alpha 0.55`（主页 9 处）。
- **注意**：改造后条目高度会从"图标 40% 约束"变为"文字撑开"，整页长度变化未知，**必须装机看首屏与滚动手感**。**需拍板（§5-Q6）**。

### 批次 7｜顶栏条件化（C1）⚠ 最高风险

两种做法，**二选一，需拍板（§5-Q7）**：
- **方案 A（保守）**：不动结构，只把顶栏的字体属性（14sp bold）显式写进 56 个文件，消除"继承主题默认"的隐式依赖。改动 56 文件但每处 1 行，风险低。
- **方案 B（彻底）**：抽 `layout/view_topbar.xml` + 56 处 `<include>`，把 `btn_refresh`/`home_btn`/`queueBtn` 等变体做成可选 id。收益大（一处改全站），但 56 个文件同时改、`setRound()` 的 findViewById 依赖 id 路径不变、每个变体都要回归。**建议放在最后做，或不做。**

### 批次 8｜图标清色（V3，仅颜色）

- 旧粉 3 种（`#FB8799`/`#fb8799`/`#fb6789`）→ `@color/bili_pink`；5 种白 → `@color/textwhite`。
- **不换图标**：22 个 iconfont(960) 与 24 个 Material(24) 的粗细/留白差异属"既有设计资产"，替换将违反"不得随意混用多套图标体系"与"不得替换核心视觉元素"。**此项作为遗留问题登记，不做**。
- 影响约 10 个 drawable。风险：低。

### 批次 9｜手表专项

- **不做新机制**。只做两件事：① 复核批次 3/4/6 改完后，圆屏 8%/6% 安全区在新增 padding 下是否仍不漏内容；② 卡片内边距是否可改为按屏宽钳制（`Math.min(dp(10), width*0.05f)`），**这一项必须真机先看当前是否真的偏大**，否则不做。
- 影响：`cell_video_list.xml` 等 6 个 cell；或零改动。

### 批次 10｜全局复查 + 构建 + 实机

见 §7。
