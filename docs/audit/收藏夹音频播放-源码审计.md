# 收藏夹音频播放：阶段一源码审计报告

> 2026-11-05。审计对象：`/tmp/NeriPlayer`（master 浅克隆）与本工作区 Re-BiliTerminal 1.2.8。
> 全程只读，未修改任何代码，未对线上接口做运行验证。

## 一、核心结论（三条）

1. **不需要新播放器内核**：`PlayerActivity` 已有纯音频模式（`audio_only` extra → `vn=1` 禁用视频解码），本地 `audio.m4a`（DASH 音频流原样落盘）就是用它播的，已验证可用。
2. **但现有"点条目起播"链路不请求 DASH**：`JumpToPlayerActivity` 走 `PlayerApi.getVideo`（`fnval=1`，只返回 durl）；`getVideoDash` 全仓仅用于下载与清晰度列表。所以要做的是**新增音频取流入口 + 队列**，不是改播放器。
3. **没有跨稿件播放队列**：现有"上一首/下一首"只作用于同一稿件的分 P。收藏夹队列需要新建独立单例，不能塞进 `PlayerData`/Intent。

## 二、NeriPlayer 技术栈与可复用边界

- Kotlin 2.4 + Compose + **Media3 ExoPlayer 1.10.1**，minSdk **28**；自写 `android.app.Service` + 平台 `MediaSession`（非 MediaSessionService）。
- 与本项目 **Java + ijkplayer + minSdk 19** 完全不同，**不能照搬播放器层**。
- 可复用（改写成 Java）：B 站 API 调用顺序、音轨选择策略、队列导航纯策略、失败分类与跳过策略、URL 失效重解析策略。

| `core/player/playback/PlaybackFailureRecoveryOwner.kt` | 失败分类：登录需求/URL 不可用；断网原地等待/跳过 |

**关键 API**：取流 `x/player/wbi/playurl`（`fnval=272`、WBI 签名）；详情 `x/web-interface/wbi/view`；分P `x/player/pagelist`；收藏夹内容 `x/v3/fav/resource/list`（与项目一致）。
**音轨选择**：普通轨按码率区间降级，DOLBY/HIRES/LOSSLESS 优先精确命中，保底最大带宽；不需要视频轨。
**URL 失效**：无显式过期字段，靠"年龄阈值 + 播放错误触发重解析 + 冷却去重"。
**失败策略**：断网 `holdForNetwork` 原地等；连续失败熔断停播、保留队列。

## 四、Re-BiliTerminal 收藏夹与播放器现状

### 收藏夹链路

| 环节 | 类 | 关键点 |
|---|---|---|
| 收藏夹列表 | `activity/user/favorite/FavoriteFolderListActivity.java` | `FavoriteApi.getFavoriteFolders(mid)` |
| 收藏夹详情 | `activity/user/favorite/FavoriteVideoListActivity.java` | 继承 `RefreshListActivity`；`mediaId<=0` 时 `FavoriteApi.mediaIdOf` 兜底；`setupSortBar()` |
| 数据接口 | `api/FavoriteApi.java:291-321` | `x/v3/fav/resource/list`，`ps=20`，`order=mtime/view/pubtime`；只保留 `type==2`；**`card.cid = item.ugc.first_cid`**（零请求拿 cid） |
| 数据模型 | `api/FavoriteApi.V3Media` | aid/bvid/`ugc.first_cid`/播放数/`attr`（非0=失效） |
| 卡片点击 | `VideoCardAdapter.java:106-110` | 进 `VideoInfoActivity`，**没有直接起播** |

### 播放器关键能力（已具备）

- `PlayerApi.getVideoDash`（`:283-306`）已解析 `dash.video/audio` + dolby + flac，`DashData.getBestAudioStream()` = flac → dolby → 最大带宽；`buildMediaCandidates` CDN 排序、`mediaHeadersFor` 按域分级请求头。
- `PlayerActivity`：`audio_only` extra（`:523-531`）→ `vn=1`/`skip_frame`（`:1271-1274`）；`setDataSource(url, mediaHeadersFor(url))`（`:1427-1432`）；进度上报 15s 节流 + 切P/退出兜底。
- 后台：`service/PlaybackService.java`（普通 Service + 通知栏，**播放器仍在 Activity 里**，Activity 挂了服务自杀）；`helper/MediaSessionHelper.java`（API21+，**默认关闭**，`onSkipToNext/Previous` 当前绑定分P）。
- 通知栏只有「暂停/播放」「关闭」两个按钮。

### 现存缺口

- 无跨稿件队列、无"播放全部"。
- **音频焦点 / 耳机拔出 / 耳机按键全仓 0 命中**（`requestAudioFocus`、`ACTION_AUDIO_BECOMING_NOISY` 均无）。
- MediaSession 默认关闭（开关在实验室）。

## 八、DASH 音频播放兼容性结论（明确）

**能，且无需新内核。** 证据：
1. `PlayerActivity.java:523-531` 已有 `audio_only` 模式（含 Intent extra 与全局偏好两条来源）。
2. `PlayerActivity.java:1271-1274` 对 ijkplayer 设置 `vn=1` 禁用视频解码。
3. `LocalVideoAdapter.java:82-88` 本地 `audio.m4a`（DASH 音频原样落盘，见 `DownloadService.java:170-179`）正是用同一播放器播放。
4. `PlayerActivity.java:410` 的 `url` extra 接受任意 http 媒体地址，`setDataSource` 带 `mediaHeadersFor` 请求头（Referer + B 站域 Cookie）。

需要补的是**取流入口**（`getVideoDash` 目前不参与播放链路）与**队列**，不是播放能力。

## 九、后台播放方案

**推荐最小方案（本期）**：沿用现有 `PlaybackService`（Activity 持有播放器、服务保活+通知栏），在音频模式下：
- 强制启用 MediaSession（仅队列模式生效，不改全局默认）；
- 通知栏增加上一首/下一首；
- 补 `requestAudioFocus`/`ACTION_AUDIO_BECOMING_NOISY`（这是现存缺口，纯音频必须补）。

**已知限制**：现有服务不持有播放器，Activity 被系统回收后播放停止。真·后台（Service 持播放器）需要较大重构，建议二期。

## 十一、分阶段实施计划

| 阶段 | 内容 | 验证 |
|---|---|---|
| P1 | 收藏夹详情页「听全部」入口 | 入口可见，普通视频播放不受影响 |
| P2 | AudioQueue + AudioQueueApi（分页加载、失效过滤、保留原顺序） | 大收藏夹加载完整、顺序正确 |
| P3 | AudioTrackPicker + AudioQueuePlayer（DASH 音频取流 + audio_only 起播） | 单条能纯音频播放，无画面 |
| P4 | 连播/上下一首（onCompletion + MediaSession + 通知栏） | 连续播放、切歌、退出恢复正常 |
| P5 | 后台与焦点（音频焦点、耳机拔出、队列模式强制 MediaSession） | 切后台/锁屏/耳机键 |
| P6 | 错误处理（失败标记/重试/跳过/熔断） | 失效条目、断网、URL 失效 |

## 十二、待确认的技术取舍

1. 入口形式：收藏夹详情页顶部「听全部」按钮（推荐，改动最小）。
2. 多 P 条目：第一版一条收藏 = 一首（取 `ugc.first_cid`），不拆分 P（与任务要求一致）。
3. MediaSession：队列模式下强制开启（否则锁屏/耳机键无效），不改全局默认开关。
4. 真·后台：本期沿用 Activity 持有播放器（切后台可播、Activity 被回收则停）；Service 持播放器留二期。
5. 音轨：固定优先 30280 AAC，不做音质选择 UI。
