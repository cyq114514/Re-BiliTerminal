# Re-BiliTerminal 屏幕自适应修复方案（阶段 B，待确认）

> 2026-11-07 · 基于《01-阶段A-审计报告》编制。**本文为方案，未获确认不改代码。**
> 最高原则：只改布局表现，不改功能行为；key/业务逻辑/主题体系零变更；不删任何功能入口。

## 一、适配标准（新增的项目级规范，修复与今后开发共用）

### 1. 圆屏安全区（新增机制，全站统一，不再逐页打补丁）
- **内容区**：`player_ui_round` 开启时，BaseActivity 对 `android.R.id.content` 统一加默认安全内边距（水平 8% 屏宽、底部 6% 屏高；复用现有 applyContentPadding 通道，用户手设 padding_percent 时以用户值为准）。装饰层（AmbientBackground）不加，继续铺满。
- **顶部**：维持 setRound() 现状（已覆盖顶栏+播放器）。
- **弹窗**：AdaptiveDialog 在圆屏时宽度比例 92%→84%（水平内缩进安全区），shadow padding 不变。
- **开关解耦**：圆屏底部 3% 补偿移出 padding_percent 分支，圆屏开关独立生效。
- 豁免：伪装页（计算器）刻意满屏，不套安全区。

### 2. 触控目标档位
- 手机 ≥48dp；手表 ≥40dp（与批次7 既有 34/38dp 衔接上浮）；发送/删除/支付类关键操作 ≥44dp。
- 实现优先 padding/touch delegate，不改控件层级；被拥挤约束时以"可点面积"而非"视觉尺寸"达标。

### 3. 字号口径（遵循 DESIGN.md 2026-11-07 收敛口径，不无差别放大）
- 角标/徽章 ≥10sp；说明/次级信息 ≥11sp（合规现状不动）；正文/标题 ≥12sp。
- 仅修违反项：9sp→10sp、非角标 10sp→11sp、正文类 11sp→12sp。波及面最大的视频卡标题 11sp→12sp。

### 4. 文本截断
- 可点文本行/卡片标题一律 maxLines+ellipsize=end（或接入 MarqueeTextView）；动态计数接 toWan 格式化上限保护。
- 修复只补缺省略号，不改变现有一行/两行行数策略。

### 5. 尺寸与约束
- 面向内容自适应的控件（二维码、封面、头像）禁止写死 ≥150dp 宽度：用 0dp+约束/百分比/maxWidth。
- 修合理的固定尺寸不动（进度条高度、图标、间距 token），不为消 lint 盲改。

### 6. 滚动与输入
- 手表可滚动容器一律 Rotary 系；Rotary 组件去掉 :50 requestFocus 抢焦点。
- RecyclerView 内含输入框的页面一律显式 `windowSoftInputMode="adjustResize"` + 聚焦滚动定位。
- span 自适应统一复用 BangumiActivity 的 screenWidthDp/120 算法（钳 2..6），不再新写档位。

### 7. 验证口径（如实区分）
- 每批 assembleDebug 编译（**不并行跑 gradle**）+ NeriPlayer 模拟器（手机形态）冒烟截图。
- 手表项全部标注"待实机"：需你在 OnePlus（手机）+ 手表（player_ui_round 开/关两态）巡检；我提供逐页清单，不代替实机结论。

## 三、不做的事（负面清单）
1. 不动任何 SharedPreferences key / 设置项语义（与设置重构任务并行，只避让不改）。
2. 不删功能、不藏入口、不改业务逻辑、不改两套播放器生命周期。
3. 不动主题/动态配色/新版美学视觉语言（安全区只是边距，不改配色与组件样式）。
4. 不无差别缩小控件/字体；不为了消静态检查警告改合理固定尺寸。
5. 播放器控制栏不做视觉重构（1.3.4 刚定稿），只调下限数值并真机回归。
