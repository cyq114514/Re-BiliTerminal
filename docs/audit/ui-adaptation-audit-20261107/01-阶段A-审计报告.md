> 方式：4 路并行子代理分域深查（全局导航/播放器/列表详情/设置弹窗）+ 主代理交叉验证与前次审计遗留复核。**未修改任何代码。**

## 1. 全局适配机制盘点（现状）

项目**不走资源限定符路线**：res/ 下仅一套 values/layout，无 -round / -sw / -land 变体；全项目 grep `smallestScreenWidthDp`/`BoxInsetLayout`/`isRound`/机型判断 均 0 命中。适配全部由代码层承担：

| 机制 | 位置 | 覆盖面 | 评价 |
|---|---|---|---|
| 应用内 DPI 缩放 | BaseActivity:74-78 → BiliTerminal:300-308（SP `dpi` 倍率） | 全部 BaseActivity 页 | ✅ 成熟；副作用：density≥72 时 fontScale 强制锁 1（P2-15） |
| 界面边距百分比 | BaseActivity:103-127,346-370（加在 content 非 DecorView） | 全部页 | ✅；但默认 0 时**内容区无任何圆屏安全边距**（P2-1 根因） |
| 圆屏适配开关 | `player_ui_round` → BaseActivity.setRound():401-479 + PlayerActivity:2052,3950 | **仅顶栏 + 播放器主控制层**；短视频域 0 命中；内容区/弹窗/列表均无消费 | ⚠️ 系统性缺口 |
| 圆屏底部 3% 补偿 | BaseActivity:114-120 | 仅当 padding_percent≠0 才走到——与"界面边距"开关隐性耦合 | ⚠️ P2-3 |

| Rotary 表冠三件套 | RotaryScrollView/Nested/RecyclerView（SOURCE_ROTARY_ENCODER） | 部分布局；**9 处裸列表未接**（P2-16） | ⚠️ 覆盖缺口 |

**核心系统性结论**：圆屏适配 = 纯手动开关 `player_ui_round`，且只补偿"顶栏 + 播放器控制层"两处。内容区（首页菜单网格、设置开关列表、二维码页、全部列表卡片、弹窗四角、短视频页）完全没有圆屏安全边距机制。这是本次审计最主要的风险面。

## 2. P1 清单（5 项，全字段）

**P1-1 首页菜单网格落圆形表下巴**
- 页面：MenuActivity（首页，全部用户必经页）
- 表现：菜单网格仅 paddingHorizontal=6dp 无底部补偿；setRound() 只重排顶栏不处理内容区。默认 16 项×2 列=8 行，滚动到底最后一行按钮+11sp 标签落入圆形可视区外，标签截断、整格难点。
- 影响：圆形表（用户主战场）｜ 证据：activity_menu.xml:41-48（已亲验）、BaseActivity.java:401-479
- 修复：player_ui_round 时给 menu_grid 加底部 8-10% 屏高 padding + clipToPadding=false

**P1-2 选P浮层 maxHeight 完全失效**
- 页面：播放页 选P/分段浮层
- 表现：`android:maxHeight="240dp"` 写在 RotaryRecyclerView 上，该类直接 extends RecyclerView 未重写 onMeasure——maxHeight 对 RecyclerView 运行时无效，浮层高度不可控（多 P 长列表可顶满全屏）。
- 影响：全部设备多 P 稿件｜ 证据：activity_player.xml:817 + RotaryRecyclerView.java:15（已亲验）
- 修复：RotaryRecyclerView 重写 onMeasure 支持 maxHeight，或 Java 按可用高度钳制

**P1-3 短视频页整体无圆屏适配**
- 页面：ShortVideoFeedFragment/cell_short_video_page
- 表现：shortvideo/ 目录 grep `player_ui_round` 0 命中（已亲验）。右侧操作栏 marginEnd=4dp、底部 SeekBar/时间戳 match_parent 贴底贴边——圆表上进度条两端、时间文字、右侧按钮落可视圆弧外。
- 影响：圆形表短视频（高频场景）｜ 证据：fragment_short_video_feed.xml:31-56、cell_short_video_page.xml:45,165-235
- 修复：复用播放页圆屏内缩套路，按屏宽比例给操作栏/底部信息加边距

**P1-4 用户空间头像约束不闭合（待实机确认）**
- 页面：用户空间头卡（UserDynamicAdapter）
- 表现：userAvatar `0dp×0dp` MATCH_CONSTRAINT 仅 start+top 两约束，宽高两轴均未闭合，配合 dimensionRatio 1:1 的回退行为随版本而异，存在塌缩为 0 或尺寸不可预测风险。同项目 cell_medal_list:15-26 有正确写法（top+bottom+height_percent）。
- 影响：全部（小屏尤甚）｜ 证据：cell_user_info.xml:9-18（已亲验）；静态分析定级，需真机确认
- 修复：参照 medal_list 补约束

**P1-5 定时发布用原生 DatePicker/TimePicker**
- 页面：发动态
- 表现：原生 picker 不跟应用内 density 覆盖缩放（AdaptiveDialog 注释实测 dpi×1.6 时系统弹窗按钮顶出屏），圆屏四角被表圈裁；且与全站 AdaptiveDialog 口径不一致（全站系统 AlertDialog 已清零，此处是漏网）。
- 影响：手表 + 开"界面大小"放大的设备｜ 证据：SendDynamicActivity.java:184,187（已亲验）
- 修复：仿 dialog_search_sort 模式 AdaptiveDialog.setView 自绘选择
