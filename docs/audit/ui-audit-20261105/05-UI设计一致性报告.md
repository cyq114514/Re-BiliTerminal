# Re-BiliTerminal UI 设计一致性报告

> 审计基线：1.2.8 · 只读 · 2026-11-05
> 结论：项目已建立完整的设计语言（"新版美学"，Re-WearBili 移植），**一致性问题的主体不是"没有规范"，而是存量代码未全部接入规范**——五种粉、四写法次级文字、两套按压语言、三套字号口径并存。逐类证据如下。

## 1. 新旧 UI 双轨现状（最大的结构性一致性问题）

| 双轨点 | 新版（默认开） | 旧版（Classic 回退 / 存量残留） | 残留位置 |
|---|---|---|---|
| 按压反馈 | press_scale 缩放动画（CardStyle/ButtonStyle） | selectableItemBackground ripple | 热搜裸行 item_hot_search.xml:9、顶栏"刷新"按钮 activity_simple_main_refresh.xml:34-48、全站列表项部分仍 ripple |
| 卡片底 | card_bg_new 30% 透明灰+发丝描边 | #cc262626 实心 | CardStyleClassic（回退层，行为正确）；Java 侧 0xcc262626 残留（SubtitleAdapter.java:82-90 等） |
| 强调色 | bili_pink #FE679A（ThemeManager 可换） | #FB7299 旧粉 / @color/pink #FBFB8787 | HotSearchAdapter.java:50、ReplyAdapter.java:150、HighEnergyProgressBar.java:42,50、sel_filter_chip.xml:9、fragment_media_info.xml:343-344、评分文字 :88、PageSelectorAdapter.java:77（0xffff6699 第四种粉！）、VideoInfoFragment.java:645（rgb(207,75,95) 第五种） |
| 菜单形态 | 圆形描边网格 cell_menu_grid | 逐个 new MaterialButton 纯文本 | MenuActivity.java:142-213 两套并存 |
| 圆角 | 10dp | 6dp（旧 token card_round 仍被引用） | VideoInfoFragment 争议角标等 |

**风险**：ThemeApplier 白名单只认 #FE679A——上表所有旧粉/自造粉在用户自定义主题下**不跟随换色**，是"换主题色后部分元素不变色"类反馈的根源。

## 2. 颜色一致性（详见资源报告 §1，此处列跨页不一致行为）

1. 同语义不同值：强调粉 ×5、次级文字 ×4（#999999/#666666/#B3FFFFFF/alpha0.7）、白 ×2（ebe0e2/FFFFFF）、蓝 ×3（00A1D6/66ccff/03a9f4）。
2. 同页面两档卡片底直接相邻（搜索历史浮层 vs 搜索框，background_searchhistory vs background_searchbar）——语义上是对的（嵌套层级），但需规范命名防止被当成"不一致"误改。
3. 视频详情页 meta 区显式声明 textColor（viewCount）与靠主题默认的同级元素混写（fragment_video_info.xml:125-145）。
4. 直播卡"[直播]"前缀走 ThemeManager.getPrimary()，番剧 Tab 胶囊硬编码——**同类强调两套口径**（VideoCardHolder.java:70-74 vs sel_filter_chip.xml:9）。

## 3. 字体一致性

1. 正文基准分裂：主题默认 14sp vs 布局事实主力 13sp（158 处）——同一列表页两级文字 13/11 与另一页 14/12 并存。
2. 标题层级弱：卡片标题多为 13sp 不加粗；页面大标题 16/17/18sp 三种。
3. 热搜页字号自成体系（16/12sp），偏离全站 13/11。
4. **35sp 作高度 42 处**——字体缩放下统一爆高，属全局性一致风险（资源报告 §2.2）。

## 4. 图标一致性

1. **返回图标三语义**：arrow_back（返回）、arrow_down（回菜单）、arrow_up（菜单回来源）——机制成立，但 SearchActivity 带 keyword 时 arrow_down 配 finish 行为、播放器弹层无图标语义等点需按 §2.1 行为矩阵对齐。
2. 系统图标残留：音频播放器上一首/下一首用 `@android:drawable/ic_media_previous/next` + 硬编码 #FFFFFF tint（activity_audio_player.xml:145-170），与全套自绘粉色图标冲突。
3. 未接入 contentDescription：152 处 ImageView/ImageButton 无障碍描述缺失（重灾区 activity_myspace 25、activity_setting_main 20、activity_player 16）——对以表冠/键盘导航的手表场景影响有限，但与"可访问性"目标相悖。
4. 封面圆角双档（6dp 图 vs 10dp 卡）需在规范中显式确认（当前疑似无意识）。

## 5. 布局模式一致性

1. 列表骨架分裂：RefreshListActivity（35 页）与 RefreshMainActivity（10 页）与"绕开基类手写"（Popular/Ranking/Precious/HotSearch 四页复制逻辑）三轨——四页因此失去：网格模式、主题色刷新圈、顶栏刷新按钮、emptyTip 接入（PopularActivity.java:49-58 等）。
2. 空态机制四分五裂：emptyTip 控件在 8 个页面闲置未用；RankingActivity 是唯一正确示范（RankingActivity.java:88,102,108-116）。
3. 裸代码 UI：CollectionInfoActivity 段标题 `new TextView(context)` 无样式 + setLeft(5) 像素 hack（CollectionInfoActivity.java:206-211）。
4. 死属性残留：fragment_video_info 多处 ConstraintLayout 属性写在非 ConstraintLayout 父容器下（:69-71,90-92,101-103 等）；activity_live_info 加载图 0dp+constraint 属性在 RelativeLayout 下（P1）。**建议整改时统一清理**。

## 6. 交互一致性

1. 返回语义三态（finish/开菜单/回菜单）设计上自洽，但存在行为与图标不符、来源页与目标不符两处偏差（见 §4.1 与页面清单 §8）。
2. 确认弹窗口径：删除/清空有的有确认有的没有（单条历史长按即删 vs 清空有确认；滑动删除菜单项无确认；恢复默认无确认）。
3. 点击即搜 vs 点击仅填入：搜索建议/历史点击即搜，热搜词点击仅 setText（HotSearchAdapter.java:71-76）。
4. toast 轰炸：SearchSort/SortSetting 进出必弹两条；番剧"已定位"每次进入弹。
5. 防抖全站缺失（列表双击双开）——单点接入统一 Util 即可全量解决。

## 7. 一致性整改方向（衔接整改规划）

1. **粉色收口**（P2，量小收益大）：5 处旧粉/自造粉 → token 或 ThemeManager 派生；顺带解决自定义主题覆盖缺口。
2. **四页列表回归基类**（P2）：Popular/Ranking/Precious/HotSearch 改继承 RefreshMainActivity，一次性补齐网格/刷新/空态。
3. **emptyTip 强制接入**（P1 批量）：空态与 page1 失败必须走空态视图。
4. **按压语言二选一**：卡片/按钮=press_scale，列表项=ripple 或统一 press_scale，页面内禁止混用。
5. **字号阶梯化**：按设计规范 §1.2 分三批对齐（13 基准确立、8-10sp 提底、35sp 清零）。
