## 追加修复（2026-11-05 用户反馈，非审计项）

### 收藏夹听歌：一次性获取收藏夹全部内容

原设计是「第一页起播 + 队列剩余不足 3 首才补一页」，长收藏夹在队列页里永远只有已播到的那几页。改为**全量拉取**：

| 改动 | 位置 |
|---|---|
| `ensureMoreItems` 重写：从已加载页下一页起串行翻页直到到底，每页到达即追加+通知（队列页实时变长、胶囊进度文案 3/57 变准）；单页失败重试 3 次（1.5s 间隔），仍败则停住，下一首 onPrepared 从断点续拉；安全上限 100 页/2000 条 | AudioPlayerService.java |
| `AudioQueue.append` 按 aid 去重（列表页翻过的多页与分页接口边界重叠不再重复入队）；`setQueue` 的 loadedPage 改按条数÷20 推算（此前固定记 1，列表页翻过 2 页时补拉会重复） | AudioQueue.java |
| `AudioQueueApi` 的 hasMore 改用接口原值：某页 20 条全是失效稿件被滤空时，后面可能还有页——此前会误判「到底」提前截断（**这正是"无法获取全部内容"的一种根因**） | AudioQueueApi.java |
| 队列页 `onAudioStateChanged` 在队列变长时同步重建列表（此前只在 onCreate 快照一次，后台补页永远不可见） | AudioQueueActivity.java |
| Service 的 prepared/playing/destroyed 标志改 volatile（全量拉取长循环跨线程读取的可见性） | AudioPlayerService.java |

起播速度不受影响（第一页立即开播，翻页在后台跑）。交接文档「决策4」已同步改写。

## 有意跳过清单（含原因）

| 项 | 原因 |
|---|---|
| 双长按删除口径（收藏/稍后/本地/分页页） | 双长按是**有意的两步确认设计**（防误触且无弹窗打断），非事故性漏洞；全量改对话框属产品决策，保留现状并记录 |
| TutorialActivity 吞返回 | 强制阅读更新说明为设计意图（X-43 豁免） |
| MsgUtil sticky SnackEvent 跨页滞留 | 「回页补显提示」是既有设计；改非 sticky 会破坏 SnackEvent 恢复链，需专项设计 |
| 46 处绕过 GlideUtil 的直调 | 逐点改造回归面大；已收口 GlideUtil 主入口 error 占位，绕过点治理建议单独立项 |
| 未引用资源删除（8 drawable + 2 布局） | release 有 shrinkResources 兜底，删除收益仅限源码整洁；留待专项清理 |
| QR 页「但是我拒绝」彩蛋、投币固定 1 币 | 产品/彩蛋性质，非缺陷 |
| SortSetting 滑动删除无确认 | 与双长按同属两步手势，保留 |
| 搜索排序/菜单排序进出双 toast | 需引入脏标记重构保存链，收益低；待后续 |
| Rotary 三件套 DRY 重构 | 行为无缺陷，纯重构；批次8 原则不动无行为问题的代码 |
| Press_scale 全站铺开 / ripple 统一 | 视觉决策需真机对比验证，留待设计规范落地后 |
