## 2. 分页面适配结论

### 2.1 已适配良好（代码证据充分）
- 菜单页（圆形描边网格、label 11sp 在表上可辨但处于下限）、推荐/历史/收藏等 simple_* 列表族（6dp 边距体系 + Rotary + emptyTip 骨架）、设置列表族（长文案换行）、番剧/搜索/动态等 InstanceActivity 页、看图页（缩放手势）、登录三通道（三档二维码缩放）。

### 2.3 需要单独设计的页面（不是"缩小手机版"能解决）
1. **播放器弹层组**：圆屏内缩 + 返回键逐层关闭 + D-pad 焦点移动——三件事绑定整改。
2. **搜索分类导航**：需要手表形态的分类入口（紧凑 Tab 条或菜单式），而非纯横滑。
3. **收藏夹批量多选**：多选工具条在 390² 下的布局（当前手机形态工具条未在手表验证）。
4. **发动态/写评论**：多行输入+表情+图片选择的组合在语音输入为主的手表上需要精简路径。

### 2.4 完全没有适配（按现状会在手表上有问题）
- 无。但「四页绕开基类」的列表页（热门/排行/珍藏/热搜）因缺网格与空态机制，在小屏横屏模式下体验低于基线（P2，一致性报告 §5.1）。

## 3. 未验证项汇总（无手表实机）
1. Rotary 表冠滚动事件与列表嵌套滚动的冲突（代码看 Rotary 系已实现让位逻辑，未实测）。
2. 390² 及以下分辨率逐页溢出扫描（布局测量推演：番剧详情长标题、播放器弹层两处确定性溢出，其余待实测）。
3. 手表输入法（语音/手写）在搜索框/私信/写评论的实际情况。
4. 圆屏开关开启后的全页面巡检（代码仅覆盖顶栏+播放器主控制层，其余页面视觉效果未实测）。
5. 低内存手表（512MB 级）连续刷列表的 GC 表现（缓存钳制已做，实测为准）。
