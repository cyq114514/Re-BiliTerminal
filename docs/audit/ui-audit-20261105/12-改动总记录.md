## 二、用户反馈①：设置开关颜色不随主题色

**根因**：开关选中色来自主题属性 `colorControlActivated`，运行时无法更改；项目已有 `ThemeApplier.applySwitch()` 但**只在界面设置页手动调了 4 个开关**，其余设置页全部留在默认粉。

**修复（机制级，一次覆盖全站）**：
| 改动 | 文件 |
|---|---|
| 全树遍历新增 `CompoundButton` 分支，自动调 `applySwitch` | `ui/theme/ThemeApplier.java` |
| `applySwitch` 扩展 CheckBox/RadioButton（buttonTint 三态重建：选中/常态/禁用） | 同上 |
| bind 末尾补 `ThemeApplier.apply(itemView)`（列表 cell 是绑定期成型，页面级换色跑不到） | `adapter/SettingsAdapter.java`、`adapter/message/MessageSettingsAdapter.java` |

**覆盖范围**：设置主页、菜单设置（7 个）、偏好设置、消息设置、隐私与伪装、实验室、首启向导、调试页等**约 20+ 个开关**全部纳入主题色体系。默认主题零改动（`apply()` 首行短路）。

## 三、用户反馈②：收藏夹听歌无法一次性获取全部内容

**四个根因（全修）**：
| # | 根因 | 后果 |
|---|---|---|
| 1 | 原设计就是「懒加载」：队列剩余<3 首才补一页 | 长收藏夹永远只装「播到哪算哪」 |
| 2 | `loadedPage` 写死 1（列表页翻过 N 页也记 1） | 补页从第 2 页重来，**重复入队** |
| 3 | `hasMore` 语义 bug：某页 20 条全是失效稿件被滤空 → 当成「到底」 | **队列提前截断——含失效视频的收藏夹拿不全** |
| 4 | 队列页只在 onCreate 快照一次 | 后台补页永远不显示 |

**新逻辑**：
```
点「听全部」→ 列表页已加载内容立即起播（速度不变）
            → 后台串行翻页直到收藏夹到底，每页到达即入队+通知
```
- `ensureMoreItems` 重写为全量拉取循环：单页失败重试 3 次（1.5s 间隔），仍败则停住、下一首 onPrepared 断点续拉；安全上限 100 页/2000 条防死循环
- `AudioQueue.append` 按 aid 去重（`aidSet`）；`setQueue` 的 loadedPage 按条数÷20 推算
- `AudioQueueApi.hasMore` 改用接口原值
- 队列页 `onAudioStateChanged` 队列变长时同步重建列表
- Service 的 `prepared/playing/destroyed` 改 `volatile`（长循环跨线程可见性）

**验证线索**：`adb logcat -d | grep audio-diag` 应见 `全量拉取 page=2 追加=20 总数=40 hasMore=true` … `全量拉取结束 本轮=N 页`。

| 项 | 内容 |
|---|---|
| 构建命令 | `./gradlew clean assembleDebug assembleRelease` |
| 产物 | `app/build/outputs/apk/release/app-release.apk`（约 9.8MB） |
| 签名 | `~/.android/biliterminal-release.jks`（别名 biliterminal），证书 SHA-256 `8557d314…`，与已装版本一致 |
| 安装方式 | `adb install -r`（同签名覆盖，登录态/数据保留）——**未发版**：versionCode/versionName 保持 20261103/1.2.8 |
| 设备 | OnePlus PJZ110（Android 17），无线 ADB |
| 编译验证 | 每批次 `assembleDebug` 全绿（共 16 次构建） |
| 未验证 | 手表实机（无设备）；模拟器 ABI 不匹配（项目只出 armeabi-v7a/x86，镜像为 arm64） |

### 环境问题（需注意）
构建中间目录 `app/build/` 多次被环境同步工具写入 `文件名 2.class` / `xxx 2.xml` 副本，导致
`D8: Type ... is defined multiple times` 与 `Failed file name validation` 失败。
**源码树始终干净**；解决方式：`./gradlew clean && rm -rf app/build`。
建议把 `app/build` 加入同步工具排除列表。
