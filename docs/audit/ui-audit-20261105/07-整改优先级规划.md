# Re-BiliTerminal UI 整改优先级规划

> 依据《02-UI问题审计报告》编制；批次按依赖关系组织——后一批依赖前一批的机制/口径，同批内可并行。
> 原则：每批收口一个"机制"而非零散修页面；每批附带验收标准，与《09-真机视觉验证清单》联动。

## 批次总览

| 批次 | 主题 | 级别构成 | 预估规模 |
|---|---|---|---|
| 批次1 | 崩溃与数据安全 | P1×5 | 小（每项 <30 行改动） |
| 批次2 | 永久性空/转圈态（加载失败兜底） | P1×5 + P2×8 | 中 |
| 批次3 | 导航与顶栏（含"点标题返回"缺口收口） | P1×2 + P2×3 | 小 |
| 批次4 | 播放器体验包 | P1×2 + P2×4 | 中 |
| 批次5 | 全局机制件（防抖/空态基建/确认口径） | P2×6（带动全站） | 中，一次性投入长期收益 |
| 批次6 | Token 收口（颜色/字号/35sp） | P2×5 + P3×30+ | 大但机械化 |
| 批次7 | 手表专项（弹层圆屏/触控面积/搜索 Tab） | P2×5 | 中 |
| 批次8 | 细节打磨（P3 清扫） | P3×40+ | 按需 |

## 批次1：崩溃与数据安全（立即，1 个版本内）

| 项 | 内容 | 验收 |

| F-01 | SettingMenuActivity 改"切换即落库"+save() 判空 | 加载中退出不崩；杀进程不丢改动 |
| A-01 | VideoInfoFragment onFinishLoad 兜底（null/异常分支也调度） | 断网进详情可见错误态 |
| D-04 | DownloadListActivity 删除加 AdaptiveDialog 确认 | 长按先弹确认 |
| X-45⚠️ | LiveInfoActivity playInfo 判空 + 取消迟到报错 | 断网进直播不崩、无迟到 toast |

依赖：无。可与任何批次并行。

## 批次5：全局机制件（基建，一次性）

1. **防抖 Util**（X-01 + E-02 + 动态/评论点赞）：统一的 250ms 点击守卫，接入全部 Adapter 与发送按钮。
2. **emptyTip 基建**（X-02 系列）：RefreshListActivity/RefreshMainActivity 提供 `showError(msg, retry)` / `showEmpty(msg)` 两态 API，附带文案差异化（失败≠空）。
3. **确认口径统一**（X-28/X-29/X-35/X-36）：破坏性操作=AdaptiveDialog；"再点一次"类确认加 3s 超时；危险设置项升级 switch_warn。
4. **windowSoftInputMode**（X-38）：三个输入页补 adjustResize。
5. **刷新注册补全**（X-03/X-14）：9 个列表页 setOnRefreshListener。
6. **主题色覆盖兜底**（G-01）：ThemeApplier 调用点补齐 5 页 + PR 自查项固化；顺带评估 ImageView src/CSL/colorControlActivated 三类覆盖策略（switch 逐实例补 tint 的现状太脆弱）。
7. **Glide 失败态**（G）：GlideUtil 统一挂 `.error()` 占位 + 治理 46 处绕过点。

## 批次6：Token 收口（机械化，建议脚本辅助+人工复核）

1. 颜色：5 种粉→token/ThemeManager 派生（ReplyAdapter/HighEnergyProgressBar/HotSearchAdapter/sel_filter_chip/fragment_media_info/VoteActivity/PageSelectorAdapter/VideoInfoFragment/OpusContentAdapter/PrivateMsgAdapter）；白色→textwhite；蓝色→bili_blue；进度色统一。
2. 35sp 高度 42 处→dp（写脚本列出后逐个确认语义）。
3. 字号阶梯对齐（8-10sp 提底、标题 14bold、meta 统一 meta_text）。
4. 死属性清理（ConstraintLayout 残留、0dp 加载图 C-03）。
5. 资源清理（重复 drawable 3 文件、未引用 8+2——先人工确认再删）。

依赖：批次2/5 落地后再做，避免改动冲突。

## 批次8：细节打磨

P3 清单按主题分组处理（视觉 Token 类大部分已随批次6；交互细节类按页面顺手修；性能类除 TimelineAdapter 复用改造外均可低优先级）。TimelineAdapter 复用改造（P2）建议与"番剧新番 tab 整体重挂"一起做。

## 依赖关系图（文字版）

```
批次1(安全) ──────────────┐
批次3(导航) ──────────────┼→ 批次5(机制件) → 批次6(Token收口) → 批次8(打磨)
批次2(空态口径) ──────────┤
批次4(播放器) ─→ 批次7(手表专项，需实机)
```

- 批次1/2/3/4 相互独立，可并行派发。
- 批次6 必须在批次2/5 之后（避免空态文案与颜色改动互相踩）。
- 批次7 建议在批次4 完成后进行（播放器改造一次到位，避免二次回归）。

## 版本切分建议

- **1.2.9**：批次1 + 批次3（安全+导航，改动小、风险低、直接回应"点标题返回"需求）。
- **1.3.0**：批次2 + 批次5（空态与机制件，跨页改动需完整回归）。
- **1.3.x**：批次4 + 批次7（播放器与手表专项）。
- **1.4.0**：批次6 + 批次8（Token 收口 + 打磨，配合设计规范发布）。
