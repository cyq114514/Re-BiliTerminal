# Re-BiliTerminal 统一 UI 设计规范（建议稿）

> 依据本次全量审计的存量证据制定；每条规范标注「现状差距」以便按清单整改。
> 适用范围：所有新页面/新组件；存量页面按《整改优先级规划》分批对齐。

## 0. 设计原则（四条，优先级从高到低）

1. **手表优先**：任何页面先保证 390x390 圆/方形手表可用，再放大到手机。禁止"手机布局缩小=手表适配"。
2. **单手 + 表冠**：核心操作拇指可达；列表必须支持 Rotary 滚动；返回永远有两个通道（标题点击 + 系统返回/菜单键）。
3. **深色即唯一**：应用为永久深色单主题。新页面禁止假设浅色、禁止硬编码纯白/纯黑（用 textwhite/bgblack/语义灰）。
4. **低配宽容**：默认主题路径零开销；动画可关；图片必须走 GlideUtil 管线；主线程禁 IO/IPC。

## 1. 设计 Token

### 1.2 字号阶梯（手表最小可读下限 11sp）

| 层级 | 字号 | 用途 | 现状差距 |
|---|---|---|---|
| display | 40sp | 计算器屏显 | 仅伪装页 |
| titleLarge | 17sp | 页面内大标题 | 现 16-18sp 散布 → 收敛 17 |
| title | 14sp + bold | 卡片标题/顶栏标题 | 现 13sp 不加粗为主 → 提为 14bold |
| body | 13sp | 正文/列表主文字 | 13sp 是事实基准，正式确立（替代主题默认 14sp 双轨） |
| meta | 11sp | 播放量/UP/时间/徽章 | 现 11-12sp 混用 → 统一 11 |
| micro | 10sp | 极少数静态标签（禁用于需阅读的内容） | 8-9sp×5 处 → 提到 10sp 起步 |

规则：**禁止 sp 作高度/宽度**（现存 42 处 `35sp` 高度 → 全部改 dp 或 minHeight）；标题必须单行省略或 Marquee。

## 2. 组件规范

### 2.1 顶栏（全局返回锚点 —— 对应"点标题返回上级"需求）

结构：`pageName（arrow_back 图标 + 标题，Marquee/单行省略）` + `timeText（TextClock + BatteryView）`；高度 wrap、水平内距 12dp。
行为矩阵（唯一真源）：

| 页面类型 | 标题点击 | arrow 图标 |
|---|---|---|
| BaseActivity 普通页 | finish（返回来源页） | arrow_back（左箭头） |
| InstanceActivity 浏览页（菜单直达的顶层列表） | 开菜单 | arrow_down（语义"回菜单"） |
| MenuActivity | finish（回到来源页） | arrow_up |
| 全屏页（播放器/短视频/看图） | 播放器=finish；短视频=回菜单；弹层打开时**返回键先关弹层** | arrow_back |

**强制**：所有非豁免页面必须有顶栏；`setPageName` 或布局 `pagename_*` 必须二选一有值。缺口：UpdateActivity、PrivacyLockSettingsActivity（P1）、JumpToPlayerActivity、DownloadActivity（P2/P3）——整改时补 `activity_base` 同构顶栏。
**现状缺陷**：SearchActivity 带 keyword 时 arrow_down 图标与 finish 行为不符；番剧/搜索等 InstanceActivity 页从非菜单路径进入时"点标题=开菜单"与用户预期冲突（整改决策：保持现状为手表范式，但图标必须与行为一致；或引入"有来源优先 finish"的智能返回，二选一后全站统一）。

### 2.2 按钮

- 主按钮：ButtonStyle（10dp 圆角 + card_bg_new + 0.5dp 描边 + press_scale）；强调操作用主题色底（现在仅追番按钮等少数处）。
- 次按钮：同形不加色。
- 危险按钮：color_danger 底或描边 + **必须 AdaptiveDialog 二次确认**（现状：恢复默认/主动崩溃/滑动删除 3 处无确认）。
- 禁用态：alpha 0.4 + 不可点击（现状 AudioPlayer 解析中 seekBar 无禁用态）。
- 高度：≥40dp（手表）；**禁止 35sp 高度**。

### 2.3 卡片与列表项

- 一级卡 CardStyle；卡内浮层 bgCardNested；两卡间距 space-md；列表项垂直内距 ≥4dp、水平 ≥6dp。
- 封面：RatioImageView + radius-cover 6dp + FIT_CENTER（Classic 回退统一，禁止 letterbox 变形）。
- meta 行：图标 12dp + meta_text 色 + 11sp。
- 列表项点击必须带反馈（press_scale 或 ripple 二选一，**同页面禁止混用**）+ 250ms 防抖（现状全站列表零防抖，P2 整改）。

### 2.4 Tab / 分类导航

- 分类 ≤5 且需要直达的页面**必须有可见 Tab 条**（现搜索页 5 类纯横滑无 Tab，P2）；Tab 选中态用 colorPrimary 文字+胶囊描边（sel_filter_chip 现硬编码 #FB7299 → 改 ThemeManager 派生）。

### 2.5 弹窗 / 浮层

- 一律 AdaptiveDialog（系统 AlertDialog 禁用——现状已达成，保持）；内容高度上限屏高 2/3；标题 14bold、正文 13sp、按钮常驻底部。
- BottomSheet 仅分享面板用；16dp 顶圆角。
- 播放器弹层：返回键逐层关闭（P1 整改）；圆屏开启时弹层随 setRound 内缩（P2 整改）。

### 2.6 状态反馈（空/错/载）

- 空态：必须用 emptyTip 控件（文案 + 可选重试按钮）。**现状 8 个页面布局自带 emptyTip 但从不显示**（推荐/热门/珍藏/热搜/番剧四 tab/动态/时间线）→ P1 批量整改：失败(page1)与空数据必须走 showEmptyView，禁止"toast+白屏"。
- 失败：page==1 失败=空态+重试按钮；翻页失败=底部提示+保留已有内容；**禁止把失败当"到底"**（现 SearchVideoFragment null→setBottom）。
- 加载：首屏 loading 期间页面不可交互但**可返回**（现 JumpToPlayer 取流中不可取消，P2）。
- Toast：仅用于轻反馈；同一操作禁止 toast 轰炸（现 SearchSort/SortSetting 进出双 toast、番剧"已定位"每次进都弹 → P3）。

## 3. 设备适配规范

### 3.1 手机（≥6.0"）
按现状布局；固定 dp 仅限头像/图标；按钮高度 ≥48dp；横屏开关打开时列表 3 列网格（CustomGridManager，现状仅推荐页接入，其余列表页 P2 补齐）。

### 3.2 小屏手机（4.5-5.5"）
依赖 6dp 边距 + weight 布局；禁止横向溢出（番剧详情长标题 P1 整改后达标）；字号阶梯不变（不缩字）。

### 3.3 方形手表（~390x390）
- 边距：用户「界面边距」默认 5%/3%；
- 列表：单列；meta 两行以内；
- 顶栏信息合并（时钟+电量+标题一行）；
- 弹窗用 AdaptiveDialog；所有可点元素落入手表可视矩形。

### 3.4 圆形手表
- 启用「圆屏适配」开关后：顶栏 pageName/时钟居中、18% 水平内边距、底部 +3%；
- **弹层与浮层必须同步内缩**（现状播放器 4 个弹层未适配，P2）；列表两侧留 10% 安全区；
- 严禁把关键按钮放四角（音频胶囊现挂右上角，圆屏下需移入安全区）。

### 3.5 DPI / 字体缩放
- 资源策略：单套布局 + 代码自适应（现状），不引入 layout-限定符（避免维护翻倍）；尺寸一律 dp、文字一律 sp；
- **字体缩放验证项**：35sp 高度清零前，设置页/表单页在 fontScale≥1.3 下逐页过检；
- 应用内 density 调整（≥72 才生效）保持现状。

## 4. 交互规范（全局守则）

1. 所有列表/卡片点击 250ms 防抖（新建统一 Util，各 Adapter 接入）。
2. 破坏性操作（删除/清空/恢复默认/杀进程重启）一律 AdaptiveDialog 确认。
3. 设置项「切换即落库」为唯一口径（现 SettingMenuActivity onDestroy 落库为反例，P1 整改）。
4. 返回键在播放器/看图内必须先逐层关闭浮层（P1 整改）。
5. 手势（右滑返回等）必须排除滑动型子控件来源（P1 整改）。
6. 未登录：入口隐藏或点击引导登录，二者取一并在同页内一致（现视频详情"稍后再看隐藏 vs 点赞 toast"混用 → 统一为点击引导）。

## 5. 落地与验收

- 新页面 PR 自查项：顶栏矩阵符合 §2.1 / 无字面色 / 无 35sp / 空错态齐全 / 手表 390² 巡检 / 防抖接入。
- 本规范与《整改优先级规划》配套：规范中每条「现状差距」均能在问题清单里找到对应问题编号。
