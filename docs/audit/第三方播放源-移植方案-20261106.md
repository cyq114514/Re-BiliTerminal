### 1.3 RE 的工程约束（影响我们的实现选择）

- `PlayerActivity` 新增了 `updateResolveHint(text)` 这种「私有侧可回灌 UI 状态」的通道，说明**播放页停止加载、
  显示进度、失败退出的状态机必须由播放页自己持有**，外部只推文本。
- 私有侧被要求「只用框架类型和公共侧已有模型通信」，反过来说：**数据模型必须放在公共侧**（我们放 `source/model/`）。
- 私有侧全用 `Class.forName` 互相调用，缺一个类也能编译——这是 RE 为「分步交付」付的复杂度成本，
  本项目**不需要**反射，直接接口调用即可。

### 1.4 审计结论

| 分类 | 内容 |
| --- | --- |
| 可借鉴的架构 | 反射/接口门面隔离（我们用普通接口即可）、播放页内解析态、预热、失败分桶后给手动选源 |
| 可参考的 UI 交互 | 「点播放 → 载入中并显示解析进度 → 失败弹选源 → 选完续播」；用真实集名而非下标对齐 |
| 可复用的业务逻辑 | 几乎没有（公共仓库无实现） |
| 必须重新实现 | 源注册/管理、搜索、线路剧集解析、取流、缓存、记忆、源管理 UI |
| 与 Animeko 体系冲突 | RE 的模型是「一个 url + referer」的扁平结构；Animeko 是「源 → 条目 → 线路 → 剧集 → 资源(Media)」四层。**以 Animeko 为准**，RE 的 `onResolved(url, referer)` 只是最后一跳的接口形态 |

## 2. 第二阶段：Animeko 数据源架构研究

### 2.1 概念分层（不能压扁成一个 URL）

```text
MediaSource（数据源，全局唯一 id）
  └─ fetch(MediaFetchRequest) → SizedSource<MediaMatch>      自动匹配（本方案不做）
  └─ searchSubjects(keyword) → List<BrowseSubject>           浏览：搜条目
       └─ browseSubject(subject) → List<BrowseChannel>       浏览：线路（可重名、可为 null）
            └─ createMedia(subject, channel, episode, sort) → Media   浏览：一集 → 一个资源
Media（资源）: mediaId 稳定 / episodeRange / properties(alliance=线路名, resolution, subtitleLanguage)
ResourceLocation.WebVideo(pageUrl, apiParameters)            真正播放要再解析一次
```

`MediaSource.kt:100-136` 明确三件事：**完整性**（一次查询返回全部集与线路）、**episodeRange 准确**、
**mediaId 稳定**。文档 `media-source.md:60-64` 说明浏览与自动匹配是两层，`fetch` 建立在浏览之上。

### 2.4 取流机制：WebView 是硬依赖

- `WebVideoMatcher.kt:17-19`：`/** 匹配 WebView 拦截到的资源. */`，`match(url, context)` 接收的是**网络请求的 URL**。
- `SelectorMediaSourceEngine.kt:319`：`matchVideoUrlRegex?.find(url)` —— 这里的 `url` 来自拦截器，不是页面 HTML 文本。
- Android 侧实现是 `app/shared/app-data/src/androidMain/.../WebViewVideoExtractor.android.kt`。
- 因此「只用 OkHttp 抓 HTML + 正则」在语义上**不等于** Animeko 的行为，只能覆盖「HTML 里直接写了 m3u8/mp4」的站点。

### 2.5 实测：纯 HTTP 能覆盖多少

### 2.6 四种方案评估

| 方案 | 可行性（Java/Android 原生） | 结论 |
| --- | --- | --- |
| A. Animeko Selector 兼容 | ✅ 配置是纯 CSS Selector + 命名组正则；已有 2742 行内核 | **主方案** |
| B. Animeko RSS 兼容 | ⚠️ RSS 源产出的是**种子/磁力**（mikan/dmhy），要播放得内置 BT 流式引擎 | **不做**（等于换一个播放器内核） |

| D. Animeko 在线资源服务 | ❌ 不存在公开的视频解析 API；线上只有静态订阅清单 | **不成立**，只在文档里说明 |

### 4.4 解析链（关键设计）

```text

  ↓ ② HtmlVideoScanner：在 HTML 里扫候选

  ↓ ③ 命中 → 直接用

  ↓ ⑤ 仍未命中且用户开启「网页嗅探」→ 隐藏 WebView 加载剧集页，shouldInterceptRequest 里跑 MediaRule
  ↓ ⑥ 仍失败 → 抛 SourceException(RESOLVE)，带上「失败在哪一级」的文案
```

`player_aaaa` 的处理：先当 JSON 解析，`url` 字段做两步解码（`unescape` → 若仍是 `NBY-` 之类非 URL，
