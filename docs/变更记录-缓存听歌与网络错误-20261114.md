## 2. 根因

### 2.1 R4：能播放却弹「网络错误」

`MsgUtil.err` 把任何 `IOException` 统一显示为应用级文案，且**丢掉调用方传的描述**：

```150:156:app/src/main/java/com/RobinNotBad/BiliClient/util/MsgUtil.java
StringBuilder output = new StringBuilder(TextUtils.isEmpty(desc) ? "" : desc + "\n");
String e_str = e.toString();
if (e instanceof IOException) {
    showMsg(context.getString(R.string.err_network));
    return;
}
```

`strings.xml:176` 的文案是 `网络错误(＃°Д°)`。播放页有 5 处后台请求把异常直接丢进这个方法：

| 行号（改前） | 请求 | 频率 |
|---|---|---|
| `PlayerActivity.java:2367` | 观看进度上报 | 播放位置每 +5 秒（`PROGRESS_REPORT_INTERVAL_MS=5000`，第 306 行） |
| `PlayerActivity.java:2397` | 在看人数 | 每 5 秒（第 2405 行 `schedule(task, 0, 5000)`） |
| `PlayerActivity.java:2427` | 字幕内容 | 用户选字幕时 |
| `PlayerActivity.java:2536` | 字幕列表 | 用户点字幕按钮时 |
| `PlayerActivity.java:2639` | 旧版弹幕 | 起播后一次 |

播放流走 ijk 自己的连接，上报/轮询走 OkHttp，两者互不影响 —— 所以出现「画面在放，却弹网络错误」。第 5 处还与 `fetchThirdPartyDanmaku` 的注释自相矛盾（注释写「失败对用户静默」，catch 里却在弹提示）。

### 2.2 R1：缓存音频只能听一个（三层叠加）

**第一层（主因）**：点条目进的是单曲播放器，根本没有队列。

```72:88:app/src/main/java/com/RobinNotBad/BiliClient/adapter/video/LocalVideoAdapter.java

        ...
        Intent player = PlayerApi.jumpToPlayer(playerData);
        if (mediaPath.endsWith("audio.m4a")) {
            player.putExtra("audio_only", true);
        }
```

`PlayerActivity` 播完默认就停（`loop_enabled` 默认 false）：

```1734:1741:app/src/main/java/com/RobinNotBad/BiliClient/activity/player/PlayerActivity.java

    ijkPlayer.seekTo(0);
    ...
} else if (auto_next_enabled && hasMultiplePages() && currentPageIndex < pagenames.size() - 1) {
```

能连播的入口只有标题栏的「听歌」按钮（1.3.3 加的）。两个反馈者点的都是列表条目。

**第二层（队列被过滤空）**：`AudioQueue.addIfAbsent` 用 `aid <= 0` 当有效性门槛，而本地缓存条目 `aid=0`：

```73:83:app/src/main/java/com/RobinNotBad/BiliClient/model/AudioQueue.java
/** 去重键：同一稿件的不同分P 是不同条目，所以必须把 cid 也算进去 */
private static String keyOf(VideoCard video) {
    return video.aid + ":" + Math.max(video.cid, 0);
}

/** 去重追加：队列里已有同 aid+同 cid 的条目跳过 */
private void addIfAbsent(VideoCard video) {
    if (video == null || video.aid <= 0) return;
    if (!keySet.add(keyOf(video))) return;
    items.add(video);
}
```

`git log -L 78,84` 显示这段从 **1.2.9 创建 `AudioQueue` 时就有**，即「听歌」按钮对缓存目录一直无效：14 个文件会全部被丢，队列为空 → `AudioPlayerActivity:134` 判定 `!isRunning() && current()==null` → 弹「没有正在播放的音频」并 finish。即使放过 aid 门槛，`keyOf` 也全返回 `"0:0"`，第一次之后全被当重复丢弃。

**第三层（播完最后一首不回卷）**：`setQueue` 无条件 `hasMore = true`，本地队列（`mediaId=-1`）也照置：

```68:70:app/src/main/java/com/RobinNotBad/BiliClient/model/AudioQueue.java
this.hasMore = true;
this.loadingMore = false;
active = !items.isEmpty();
```

播完最后一首时 `onCompletion` 进入「等待补页」，拿 `mediaId=-1` 请求收藏夹必然失败，`waitingForMore` 永不复位，列表循环回不到第一首。

## 3. 修法

| # | 位置 | 改法 |
|---|---|---|
| 1 | `PlayerActivity` 7 处 catch | 进度上报/在看人数/旧版弹幕改 `Logu.w` 静默；字幕改「字幕加载失败 / 字幕获取失败」；切P/切清晰度只留一句失败提示（原来会同时弹「网络错误」+「切换失败」两条） |
| 2 | `AudioQueue.isLocalItem` / `keyOf` / `addIfAbsent` | 本地条目按 `localPath` 判有效、按 `"local:" + path` 去重；非本地仍按 `aid+cid` |
| 3 | `AudioQueue.setQueue` | `hasMore = mediaId > 0` |
| 4 | `AudioPlayerService.onCompletion` | 等待补页前加 `mediaId > 0` 守卫 |
| 5 | `AudioPlayerService.ensureMoreItems` | `mediaId <= 0` 直接 `setHasMore(false)` 返回，不再发 3 轮无效请求 |
| 6 | `LocalVideoAdapter` | 新增 `OnAudioItemClickListener`；`audio.m4a` 单条点击回调宿主 |
| 7 | `LocalListActivity` | `buildAudioItems()` 组装队列、`startAudioQueue(startIndex)` 起播并打开听歌页、`audioIndexOf()` 把列表下标换算成展开下标；听歌按钮传 0 |
| 8 | `LocalPageChooseActivity` | 整组都是音频时整组进队列，从所点 P 起播；混合组仍进内置播放器 |

防御：两处 `startAudioQueue` 在 `startQueue` 之后检查 `AudioQueue.get().current()`，为空时提示「这些缓存无法加入播放队列」而不是打开一个只会报错的听歌页。

## 5. 已知限制与未验证项

| 项 | 说明 |
|---|---|
| 第一版漏检（我的问题） | 第一版只修了「点条目进队列」与「hasMore」，**没有验证 `setQueue` 内部还有 aid 过滤**，装机后用户直接撞到「没有正在播放的音频」。第二版才定位到 `addIfAbsent`，这是我的漏检，不是用户环境问题 |
| 队列会收视频文件 | `buildAudioItems` 沿用「听歌」按钮的旧口径：把缓存里**所有** media 文件都作为条目，点音频条目时同列表的 `video.mp4` 也会占位（ijk 禁视频轨能出声，但按视频码率下载）。是否只收 `audio.m4a` 属于行为取舍，未擅自改 |
| 点音频=换页面 | 点纯音频条目现在进全屏听歌页，不再进内置播放器。保留播放器入口需回退 `LocalVideoAdapter` + `LocalListActivity` 两处 |

| R4 覆盖面 | 只改播放页 7 处；登录、下载、动态等页面仍会因 `MsgUtil.err` 弹「网络错误」（全局行为，未动） |
