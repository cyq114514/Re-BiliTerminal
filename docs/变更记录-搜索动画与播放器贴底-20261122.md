# 变更记录：搜索页动画零布局 / 播放页文字贴底 / 关注列表分批插入（2026-11-22）

## 1. 搜索页 S1：动画期间不再逐帧改 padding

**改动**：`SearchActivity.animateHeader()`

- 进入动画时一次性把 `viewPager` 的 padding 设到目标值（全流程唯一一次 layout），
  再用 `viewPager.setTranslationY(contentOffset - targetPad)` 把内容拉回当前视觉位置；
- 动画期间只改 `header` 与 `viewPager` 的 `translationY`（渲染属性，不触发布局）；
- 动画结束 `translationY` 归零，`syncTabsPadding()` 兜底页签高度变化；
- `restoreHeader()` 补 `viewPager.setTranslationY(0)`，避免中途搜索留下错位。

**真机数据（PJZ110，搜索 bilibili，一次上滑触发收起）**：

| 指标 | 改前 | 改后 |
|---|---|---|
| 动画窗口内 UI >2ms 帧 | 12 帧连续（22–166ms），平均 3.29ms | 2 帧（198/242ms） |
| 全部帧 UI >2ms | 12 / 120 | 5 / 81（含 fling 自身布局） |
| 普通帧 UI 平均 | 0.359ms | 0.339ms |

## 2. 播放页 P1：底部文字与 CC 字幕贴底

**改动**：`PlayerActivity.fadeControls()`

- 控制栏收起时，按实测布局算 `delta = layout_control.getHeight() - bottom_text_bar.getBottom() - 6dp`；
- `bottom_text_bar` 与 `text_subtitle` **各自**做 150ms `translationY(delta)`（字幕锚在文字条上，
  translationY 不会互相带走）；展开时归零。

**真机验证**：

- 进度/在线人数：收起后 `bottom_text_bar` bounds `[0,3021][1440,3080]`，屏幕高 3168，
  底边距屏幕底 88px（约 22dp），已贴底；展开时回到卡片上方（截图 `p1-after.png` / `p1-auto-hide.png`）。
- **CC 字幕未验证**：测试视频只有画面内烧录字幕，没有可切换的 CC 轨，`text_subtitle` 始终 GONE。
  代码与进度条同一段逻辑、同一 delta，但**没有真机证据**，需要找带 CC 轨的视频复测。

## 3. 关注列表 D1：分页结果分批插入

**改动**：`FollowUsersActivity.appendInBatches()`

- 一页超过 10 条时按每批 8 条、间隔 16ms 逐帧插入；数据顺序与最终内容不变；
- 页面销毁或适配器被替换（下拉刷新）时丢弃剩余批次。

**真机数据（PJZ110，连续 4 次快速滑动触发 pn=2..5）**：

| 分页 | 改前 | 改后 |
|---|---|---|
| pn=2 | 111ms / 3 帧 | 44ms / 1 帧 |
| pn=3 | 66ms / 1 帧 | 66ms / 1 帧 |
| pn=4 | 66ms / 1 帧 | 66ms / 1 帧 |

首屏峰值（3 帧）降为 1 帧，但单帧 55ms 的毛刺仍在，说明主要开销不只在“20 条同帧插入”，
还可能包含头像解码/Glide 过渡或单个 item 的布局。手表上待复测。
