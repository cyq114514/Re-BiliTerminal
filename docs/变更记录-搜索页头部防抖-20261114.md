# 变更记录：搜索页头部收起/展开防抖（2026-11-14）

> 对应输入：用户报告「搜索页进行搜索的时候，往下划的时候别松手慢慢往下划，搜索和分类栏会反复收起然后又出现」（附截图）。
> 两轮迭代：v1 方向累计器 + 同步动画（阈值 24dp）复测「仍然会闪」；v2 阈值提到 48dp 并加「一次手势一次翻转」，**用户真机测试通过**。
> 版本号未改动（`versionName 1.3.6` / `versionCode 20261116`），同签名 release 测试包交付自测，**本批改动尚未提交**。

## 0. 根因

两层叠加：

1. **触发层**（1.2.8 起就存在，当时只收一根搜索框，动静小）：`SearchActivity.onScrolled` 按单帧 dy 符号翻转头部显隐——收起条件 `dy > 0`（**任意 1px** 就收）、展开条件 `dy < -1`（2px 就放）、200ms 节流。慢速拖动时每帧只有 1~3px，人手微停顿/轻微回抖就让单帧 dy 反号，于是一次不松手的长拖里反复翻转。`dy` 的来源枚举穷尽后只有三个：触摸滚动（`SearchFragment.java:90`）、翻页 `onScrolled(256)`（`SearchActivity.java:207`）、列表顶 `-114`（`SearchFragment.java:65`）；`CustomLinearManager` 与 `ImageAutoLoadScrollListener` 均无滚动注入。
2. **放大层**（576aa49 引入）：搜索框与页签合成 `search_header` 后，「收起 GONE / 展开 VISIBLE」各自硬切一次 viewPager 约 42dp 的 `paddingTop`（且 GONE 是 `postDelayed(200)` 埋的回调，存在与后续展开打架的隐患），每次翻转列表内容猛跳一截——又诱发用户补偿性回拉，形成正反馈。截图里头部悬在结果上、首卡顶到搜索框背后，正是翻转中途的状态。

v1（方向累计器 24dp + 同步动画）后复测仍闪的原因：收起触发后累计器清零，慢拖状态下的犹豫回拉 1~2 秒就能重新累计出反向 24dp——**阈值只让循环变慢，没有掐断**。断根需要把翻转频率限制到手势粒度。

## 1. 变更摘要

2 个文件，+147 / -37（`git diff --numstat` 实测）。

| 文件 | 增删 | 内容 |
|---|---|---|
| `activity/search/SearchActivity.java` | +141 / -36 | 触发层与动画层整体重做（见下 1~7） |
| `activity/search/SearchFragment.java` | +6 / -1 | 列表顶 `-114` 改强制路径；新增滚动状态边界转发 |

分项：

1. `onScrolled` 拆成 `onScrolled(dy)` / `onScrolled(dy, force)`：force 路径（`-114` 列表顶强制展开、`256` 翻页强制收起）不经累计器，且不再被旧版 200ms 节流吃掉列表顶的强制展开。
2. **方向累计器** `scrollAccum`：同向累加、反向清零，跨过 `HEADER_TOGGLE_ACCUM_DP = 48dp`（约半行卡片高度）才翻转；同向重复越阈不重置（无害，反向第一帧自然清零）。
3. **一次手势一次翻转**：`headerToggleUsed` 在手势边界解锁——`onRecyclerViewScrollState`（`SearchFragment` 新转发）在 `DRAGGING` 进入 / `IDLE` 回静止时解锁并清零累计器；手势中途反向累计再大也不翻。旋转表冠只走 `SETTLING` 不进 `DRAGGING`，`IDLE` 解锁保证手表上不会用一次就锁死。
4. **同步动画** `animateHeader`：单个 ValueAnimator（250ms）同时驱动 header `translationY` 与 viewPager `paddingTop`，内容随头部平滑退让/让位，不再中途硬切跳变；动画结束才 `GONE`。方向反转时从当前位置续走：旧动画先摘牌再 `cancel`，收尾监听用 `a != headerAnimator` 挡掉被顶掉的旧收尾（`cancel` 会同步触发 `onAnimationEnd`，不能让它把半路的显隐落定）。
5. `syncTabsPadding` 加 `headerAnimating` 守卫：动画每帧改 padding 会触发页签 `onLayoutChange` 每帧回调这里，动画期间必须让位；落定时收尾监听补调一次结算。
6. `restoreHeader`：`searchKeyword` 复原头部前先 `cancelHeaderAnimation`，否则在跑的收起动画收尾会把它重新 `GONE` 掉。
7. 删除 `animate_last`（200ms 节流）与 `ObjectAnimator` 依赖，换 `ValueAnimator` + `AnimatorListenerAdapter`。

无新增依赖、无新增资源、无布局/API 变更；两处改动均可 `git checkout -- <文件>` 单文件回滚。

## 3. 已知限制与未验证项

- 拖动中途反向不再立即回首栏（手势锁的既定代价），松手后的下一次手势才恢复；用户在方案批准时已接受。
- 48dp 阈值 + 手势锁的叠加手感只过了用户一轮真机测试，后续如嫌"收起太迟钝/展开要用劲"再调 `HEADER_TOGGLE_ACCUM_DP` 单个常量即可。
- 「头部可见时首卡上沿被盖住一截」：`syncTabsPadding` 只补页签行没补搜索框行的老问题（576aa49 之前就存在），本批未动，要修另出方案。
- 模拟器未复现（需要 B 站登录态），全程以用户真机为准。
