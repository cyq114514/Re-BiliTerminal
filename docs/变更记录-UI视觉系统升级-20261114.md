### 1.1 与方案的四处偏离（主动说明）

1. **批次 5 比方案保守**：方案写「alpha 收敛到 2 档（0.7/0.5）」，实际**保留 0.9 档**，只把孤值（0.95/0.88/0.86/0.85→0.9，0.78/0.75/0.8→0.7，0.6/0.55→0.5）归并。
   **Why**：0.9 有 33 处、语义是「描述文字」，强归到 0.7 会让全站描述整体变淡 20%，属明显观感变更；而用户本轮不装机测试，风险不可控。
2. **批次 4 没有改 Java 着色（R1 的「雷」没拆）**：`sel_filter_chip` 选中态仍是写死的 `@color/bili_pink`，自定义主题下不跟随。
   **Why**：全项目 7 个引用页面里，4 个第三方源页面都不调 `setSelected()`（选中态根本不显示），只有 SearchActivity / BangumiActivity 调且它们本来就在 Java 里重建背景。为此写 `StateListDrawable` 重着色会引入「XML + Java 双份定义」，违反「不为抽象而抽象」。已在 drawable 注释与审查文档 §3 R1 登记。
3. **批次 6 没有重构 38 个卡片结构**：只统一字号与分组标题，没换成 `cell_setting_open` 模板。
   **Why**：38 段卡片的 id 全被 `SettingMainActivity` 引用，换结构等于重写页面并回归 120+ 设置项跳转，与「最小改动」冲突。
4. **图标白色只统一了 7 个功能图标**：`icon_bilimember`（会员角标）保留 `#FDFEFF` 纯白。
   **Why**：它压在粉色角标底上，换成暖白 `#ebe0e2` 会发脏。
5. **动效批次（11）第一版改错了**：最初按惯例在 layout 里加 `android:stateListAnimator="@animator/press_scale"`，
   dump APK 时发现该属性**根本没进包**——AAPT2 会按 `minSdk=19` 把 API 21 才引入的属性从 layout 里剥掉
   （style 里的同属性不剥，所以 `CardStyle` 的卡片缩放一直生效）。
   改成 `ToolsUtil.applyPressScale(view)` 在 4 个 Adapter 里代码设置后才真正生效。
   **顺带发现**：`cell_menu_grid` 从 1.3.x 起就写着这个属性，**主菜单的按压缩放其实一直没生效**，本批一并修好。

## 3. 已知限制与未验证项

1. **没有任何实机验证**（用户明确表示本轮不用测试）。所有结论来自静态代码 + 编译 + 产物资源 dump，**没有一个像素被真实看过**。
2. **观感变化未验证**，至少五处风险点：
   - 卡片间距 2dp→4dp：手表首屏可见条数会少约半张卡；
   - 设置页标题 12sp→14sp：38 个条目整体变高，页面变长，图标是「卡片高度 40%」约束，会跟着变大；
   - 输入框描边 2dp→0.5dp：登录页/发评论框从「粗灰框」变「发丝框」，是本次变化最明显的一处；
   - chip 未选中态从「8% 黑」变「卡片灰+描边」：筛选条整体会变亮一档；
   - 图标纯白→`#ebe0e2`：理论上差 5% 亮度，暗底上几乎无感，但未实看。
3. **`sel_filter_chip` 的选中态仍不跟随自定义主题**（见 §1.1-2）。当前无页面显示该状态，真出问题要按 DESIGN.md 在调用方用 `ThemeManager.getPrimary()` 重建。
4. **圆屏适配只做了「未破坏」的静态复核**：没有新增资源限定符、没改 `BaseActivity` 的 8%/6% 通道，但 `list_margin_vertical` 加大后圆屏底部的最后一张卡是否被切，无法静态判断。
5. **`styles.xml` 的伪注释改成真注释后，编译通过**——这次是实测（clean 后全量编译），不再是推断。
