## 这是什么

「Re：哔哩终端」是基于 **哔哩终端（BiliClient，原项目已停更归档）** 的**非官方分支**，
面向**低配手机 / 手表 / 老设备**。

相对上游，本分支主要做了三件事：

1. **品牌与安装隔离** —— 应用更名为「Re：哔哩终端」，包名改为 `com.RobinNotBad.BiliClient.re`，
   可与原版「哔哩终端」**同时安装、互不覆盖**。
2. **修番剧相关的观看进度问题** —— 本分支最初的立身之本。
3. **动态功能增强** —— 1.1.0 起补齐动态侧能力：带图发动态/带图发评论、投票、置顶与可见范围、
   编辑与发布选项、话题页，并大幅提升图文动态详情的打开速度（接口实现参考
   [PiliPlus](https://github.com/bggRGjQaUbCoE/PiliPlus) 的开源实践）。

### 1.1.0-fix1 修复了什么

**搜索建议（三连修）**

- **建议永远为空**：B站 suggest 接口的词表从 `data` 移到了 `result` 字段，旧解析取 `data.tag` 恒为空。
  现改为 `result`/`data` 双字段兼容解析，接口再挪字段也不会悄悄失效。
- **建议卡片回弹**：点击联想词后卡片重新弹出、盖住搜索结果——点击会经 `setText` 触发一次新的建议
  请求，旧代码没有在搜索执行时作废它。现搜索执行期间整条建议链路被屏蔽（含输入法延迟 commit），
  并作废在途请求、主动收起卡片。
- **建议结果被整包丢弃**：结果回调以"输入框此刻是否持有焦点"为显示条件，而部分 ROM 输入法
  （一加13 / ColorOS16 实测）在组词/候选期间会让输入框短暂失焦，导致建议永远不出现。
  现改为代际令牌校验——只显示最新一次输入的响应，同时防乱序竞态覆盖。

**搜索后输入法无法拉起（一加13 / ColorOS16）**

- 搜索执行时 `clearFocus()`、完成后 `requestFragmentFocus()` 把焦点交给结果列表；第一次点击输入框
  只恢复焦点不拉起键盘，第二次才正常；而键盘弹出引发的列表滚动回调又会触发焦点抢占，把刚弹出的
  键盘顶掉。现改为：输入框点击时主动补一次 `showSoftInput`；输入框持有焦点期间
  `requestFragmentFocus` 不再抢占焦点（手表滚轮导航不受影响）。

**低性能设备（W527 手表）转场动画丢失**

- 诊断：关于页新增动画缩放显示（无开发者选项的设备无法查看系统设置）。实测 W527 ROM 将
  `TRANSITION_ANIMATION_SCALE` 设为 0——系统级页面转场被整体禁用，该设置从应用侧无法恢复
  （需 adb / 系统权限）。
- 缓解：页面内容就绪后按"帧数"驱动渐入（帧数 + 时间双上限），把占位屏 → 内容的硬切变成过渡。
  按帧数而非时间驱动是关键：单帧绘制耗时会超过动画时长，时间型淡入在首帧画完时就已结束。

### 1.1.0 主要更新（动态功能增强）

**发布侧**

- **带图发动态**：走 web 端 `upload_bfs` 图床，最多 9 张；GIF 动图与 PNG 透明图原样透传，其余按最长边 2048 缩放压缩（按 EXIF 转正）；带图发布使用 `scene=2`。
- **带图发评论**：走新版 `/x/v2/reply/create`，根评论可附图（楼中楼不支持，需评论区开启图片评论）。
- **表情以 type 9 节点发布**：发布前拉取使用中的表情包做白名单，`[xxx]` 文本转真实表情节点，不再是纯文本。
- **转发自动引用**：转发动态、分享视频时自动构造 `//@原作者: 原内容`，原作者为可点击节点。
- **发布选项**：仅自己可见、关闭评论、定时发布（`option` 字段；定时限制 6 分钟后～7 天内）。

**动态页**

- **投票**：动态内投票卡与正文投票节点可点开参与（`vote_info` / `do_vote`），支持图片投票与多选（超出可选数先进先出替换），已投/过期显示百分比与票数。
- **动态操作菜单**：自己的动态点「删除」按钮弹出菜单——置顶/取消置顶（`set_top`/`rm_top`）、公开↔仅自己可见（`private_pub_setting`）、编辑纯文字动态（`edit/dyn`，WBI 签名）。
- **信息增强**：卡片显示评论数并可直达评论区；发布时间旁显示「参与了投票」等动作文案与「仅自己可见」徽标。
- **富文本可点击**：#话题# 进话题动态页（`feed/topic`）、BV 号进视频页、商品/抽奖/网页链接外链；表情图片 URL 多级回退。
- **话题动态页**：复用动态列表框架，隐藏发动态入口与 UP 列表。

**性能与修复**

- 图文动态详情改为 `opus/detail` 接口直取 —— 原先抓取 `www.bilibili.com/opus/{id}` 的 SSR 整页再抠 JSON，需 2~3 秒，现 1 秒内；HTML 抓取仅作接口异常时的兜底，cv 专栏路径不变。
- 修复视频转发时转发场景未被识别的问题；修复图片评论部分字段解析不兼容的问题。

### 1.0.2-fix1 具体修了什么

**观看进度上报（番剧续播进度写不进服务端）**

- 上报凭证不再读本地快照 `csrf` / `mid`，改为从实时 Cookie（`bili_jct` / `DedeUserID`）派生。
  原实现下 Cookie 轮换后两者会错位，导致**所有 POST 返回 `-111`，而 GET 一切正常** ——
  表现为「只有观看记录上报静默失效」，且同一份代码在不同设备/登录时机表现不同。
- 心跳接口的 `start_ts` 夹到 `>= 0`，避免设备时钟偏慢时被服务端判 `-400`。
- 上报前若 `mid` 为 0，用实时 Cookie 补一次解析，避免已登录却被判未登录。
- 番剧续播进度在 `x/player/wbi/v2` 取不到时，兜底走观看记录列表接口。
- WBI 密钥取成功后才落 `last_wbi`，缓存为空强制刷新，避免一次取密钥失败污染当天所有 WBI 请求。

**跳转后弹幕卡死 / 退出播放后整个应用卡死**

- 弹幕绘制线程不再轮询 `ijkPlayer.getCurrentPosition()`。该回调跑在弹幕同步/绘制线程上，
  而它是会取播放器原生锁的 JNI 调用 —— 既是「弹幕时间轴被旧位置拽住」的直接原因，
  也是绘制线程卡住后主线程 `release()` 内 `join()` 无限等待、**整个应用卡死**的共因。
- 退出链路（`finish` / `onPause` / `onStop` / `onDestroy`）与 MediaSession 状态更新
  不再在主线程调用 `getCurrentPosition()`。
- 弹幕未 `prepared` 时的 seek 请求会暂存、prepared 后补做；新增带观察窗与冷却的弹幕时间轴校正。
- DanmakuFlameMaster 的 `Thread.join` 加 2s 超时，避免主线程被无限阻塞。
- 所有 `TimerTask` 加异常兜底（TimerTask 抛未捕获异常会永久终止整个 Timer，
  导致进度条与进度上报一起静默失效）。

## 构建

```bash
git clone https://github.com/cyq114514/Re-BiliTerminal.git
cd Re-BiliTerminal
# 需要 JDK 17+ 与 Android SDK（compileSdk 33）
./gradlew :app:assembleDebug     # 调试包
./gradlew :app:assembleRelease   # 正式包（需自行配置签名）
```

Release 签名通过项目根目录的 `local.properties` 读取（该文件已在 `.gitignore` 中）：

```properties
sdk.dir=/path/to/Android/sdk
KEY_PATH=/path/to/your.jks
KEY_PASSWORD=******
ALIAS_NAME=******
ALIAS_PASSWORD=******
```

> **`KEY_PATH` 必须是纯 ASCII 路径。** `local.properties` 会被 `Properties.load()`
> 按 ISO-8859-1 解析，路径里一旦含中文就会读成乱码，导致 `validateSigningRelease`
> 报 `keystore file not found`。

## 技术栈

- **语言 / 界面**：Java + XML（`minSdk 14`，无 Kotlin、无 Compose）
- **播放器**：`ijkplayer-java`（模块内置，源自 [bilibili/ijkplayer](https://github.com/bilibili/ijkplayer)）
- **弹幕**：`DanmakuFlameMaster`（模块内置，已打本地补丁）
- **网络 / 解析**：OkHttp 3.12.1 · Gson 2.8.9 · protobuf-javalite（弹幕协议）
- **其他**：Glide、EventBus、jsoup、PhotoView、zxing、Brotli（`brotlij` + brotli4j）

## 已知问题

- 观看进度依赖服务端接口，**未登录时不会上报**（日志中会有明确提示）。
- 使用外部播放器（小电视 / 凉腕）时拿不到播放结束时的真实进度，会用进入播放前的进度兜底。
- 部分界面文案（如初始引导页里的 QQ 群与官网信息）**仍沿用上游**，未随本分支更新。
- 只打包 32 位 ABI，极少数纯 64 位设备无法安装。
- 编辑动态仅支持**纯文字**动态；带图、带转发内容的动态暂不支持编辑。
- 图片评论依赖评论区开启该功能，楼中楼（子评论）不支持带图。
- 动态侧尚未实现：投票创建、匿名投票、话题页排序切换。
